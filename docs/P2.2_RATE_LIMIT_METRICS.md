# P2.2 Rate Limit Metrics Implementation

**Date:** 2026-01-05
**Status:** ✅ Complete
**Build Status:** Pending verification

## Overview

Rate limit metrics tracking has been implemented to proactively monitor and alert on API rate limit consumption. This prevents unexpected polling failures and provides visibility into multi-tab usage patterns.

---

## Problem Solved

### Before Implementation

**Issues:**
- ❌ No visibility into rate limit consumption
- ❌ Rate limit exceeded errors appeared without warning
- ❌ Multi-tab usage could silently exhaust quota
- ❌ No way to detect approaching limits proactively

**Result:** Users experienced sudden polling failures with no advance notice.

### After Implementation

**Benefits:**
- ✅ Real-time rate limit monitoring
- ✅ Visual indicator in development mode
- ✅ Automatic warnings at 30% remaining
- ✅ Critical alerts at 10% remaining
- ✅ Sentry tracking for quota issues
- ✅ Console warnings for developers

## Features Implemented

### 1. Edge Function Rate Limit Metadata

**File:** `supabase/functions/market-data/index.ts`

**What Changed:**
```typescript
// BEFORE: Headers only
return new Response(
  JSON.stringify({ quotes }),
  {
    headers: {
      'X-RateLimit-Limit': '100',
      'X-RateLimit-Remaining': '95',
      'X-RateLimit-Reset': '1234567890',
    }
  }
);

// AFTER: Metadata in response body
return new Response(
  JSON.stringify({
    quotes,
    rateLimit: {
      limit: 100,
      remaining: 95,
      reset: 1234567890,
    },
  }),
  { headers: { /* same headers */ } }
);
```

**Why:** Supabase Functions SDK doesn't expose response headers, so we include rate limit data in the response body for client access.

### 2. useMarketData Hook Enhancements

**File:** `src/hooks/useMarketData.ts`

**New State:**
```typescript
interface RateLimitInfo {
  limit: number;           // Total requests allowed per window
  remaining: number;       // Requests remaining
  reset: number;           // Timestamp when quota resets
  percentRemaining: number; // Calculated: (remaining/limit) * 100
}
```

**Tracking Logic:**
```typescript
// Extract from response
const { limit, remaining, reset } = data.rateLimit;
const percentRemaining = Math.round((remaining / limit) * 100);

// Dev mode console warning (< 20%)
if (import.meta.env.DEV && percentRemaining < 20) {
  console.warn(`[Rate Limit] Low quota: ${remaining}/${limit} (${percentRemaining}%)`);
}

// Sentry breadcrumb (< 30%)
if (percentRemaining < 30) {
  addBreadcrumb('Rate limit approaching', {
    remaining,
    limit,
    percentRemaining,
  });
}

// Sentry error (< 10%)
if (percentRemaining < 10) {
  captureError(new Error('Rate limit critically low'), {
    remaining,
    limit,
    percentRemaining,
    resetAt: new Date(reset).toISOString(),
  });
}
```

### 4. Alert Thresholds

| Threshold | Action | Visibility |
|-----------|--------|------------|
| **100% → 31%** | None | Normal operation |
| **30%** | Sentry breadcrumb | Logged for context |
| **20%** | Console warning | Developers alerted |
| **10%** | Sentry error | Team notified |
| **0%** | Rate limit error | Polling stops |

**Escalation Path:**
1. **30% remaining** → Background monitoring (breadcrumb)
2. **20% remaining** → Developer warning (console)
3. **10% remaining** → Team alert (Sentry error)
4. **0% remaining** → User-visible error (toast + stop polling)

## Troubleshooting

### Indicator Not Showing

**Symptom:** No rate limit indicator visible

**Checklist:**
1. ✅ Running in development mode? (`npm run dev`)
2. ✅ On Dashboard or Overlay page?
3. ✅ At least 1 ticker added?
4. ✅ Market data fetched successfully?

**Debug:**
```typescript
// Check state in DevTools
const { rateLimit } = useMarketData(tickers, true);
console.log('Rate limit:', rateLimit);
```

### Warnings Appearing Too Often

**Symptom:** Constant rate limit warnings in console

**Possible Causes:**
1. **Multiple browser tabs** → Close extra tabs
2. **Short polling interval** → Increase to 30+ seconds
3. **Many tickers** → Reduce ticker count
4. **External requests** → Check for other API calls

**Solution:**
```typescript
// Increase polling interval
const { settings } = useOverlaySettings();
// Update refreshInterval to 30 or 60 seconds
```

### Critical Alerts in Sentry

**Symptom:** Receiving "Rate limit critically low" errors

**Immediate Actions:**
1. Check how many browser tabs are open
2. Review polling interval (should be ≥15s)
3. Verify no external scripts hitting the API
4. Consider increasing rate limits (edge function env vars)

**Long-term Solutions:**
- Implement tab coordination (shared worker)
- Add server-side caching layer
- Increase edge function rate limits
- Switch to WebSocket for real-time updates
